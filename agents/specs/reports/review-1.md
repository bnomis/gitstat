## Choices made (approve or flag)

1. **Unbuilt resources are never synced.** The default groups are `activity,flow`, so `resources_for` returns `commits`, `issues` and `pull_requests`, and `Fetcher.sync` raises `NotImplementedError` for the last two until step 6. The fetch spec gains `BUILT_RESOURCES` (today `{'commits'}`, each later step adds its own), and the CLI syncs `resources_for(groups) & BUILT_RESOURCES`. `flow` then shows under Unavailable, as the stats spec already arranges. (Tasks 2 and 8)
2. **A bare `NAME` is resolved with REST `GET /users/{login}`, not GraphQL.** 1.1 said resolve it "and reject as ambiguous if it is both". GitHub user and organisation logins share one namespace, so a name is never both; the REST user endpoint's `type` field says which ([Get a user](https://docs.github.com/en/rest/users/users#get-a-user)), a positive signal as the shared design rule asks. A new GraphQL query would add a `query:<NAME>` hash to the cache identity and make every existing cache raise `CacheVersionError`, which REST avoids. The ambiguity clause is dropped. With `--no-fetch` a bare `NAME` is a usage error asking for `user:` or `org:`. (Tasks 2 and 7)
3. **`--max-age` is decided in the CLI from `Fetcher.provenance`.** "Skip the network for a subject synced more recently than that" needed a definition: the sync is skipped when `fetch.max_age` is above zero and every `fetched_at:<resource>` (the oldest sync time over the subject's cached repos) is younger than it. A subject with no cached repos reads `never` and syncs. `--full-refresh` overrides it. No fetch change is needed. (Task 8)
4. **No token is needed for a report that makes no requests.** With `--no-fetch` or a fresh `--max-age`, the `Fetcher` is built with an empty token and never entered, so no aiohttp session exists. This is what makes the step's "Done when" (a report from a warm cache with no network) true without `GITHUB_TOKEN`. (Task 8)
5. **The step's "Done when" names `--no-fetch` or `--max-age`.** `fetch.max_age` defaults to zero, so `wambatic report repo:OWNER/NAME --by month` alone always syncs (listing the repo is one request). The implementation order now says the warm-cache report is run with `--no-fetch` or a `--max-age` the cache is younger than. (Tasks 8 and 12)
6. **`--format html`, `--out` and `serve` wait for their steps.** Step 5 builds `report` and `cache`. `--format html` (on the command line or as `report.format` in the config file) is a usage error naming step 7; `--out` is added with it; `serve` is not a command until step 9. (Task 7)
7. **Flags that set a setting go through `load_settings`.** `--format`, `--max-age` and `--tz` become overrides of `report.format`, `fetch.max_age` and `stats.timezone`, so a malformed value is a `SettingsError` (exit 2) with the settings layer's message, as 1.1's error list already said. An unknown zone, from the flag or the config file, is a `SettingsError` naming `stats.timezone`. (Task 7)
8. **Strict target and date syntax.** Logins are 1 to 39 ASCII letters, digits and `-`; repo names 1 to 100 of letters, digits, `.`, `_` and `-`; dates are exactly `YYYY-MM-DD` (Python 3.11+ `date.fromisoformat` also accepts `20261029` and week dates, which would be surprising here). Everything else is a usage error before any cache or network access. (Task 7)
9. **`--ignore-cache-version` on `report`.** `CacheVersionError`'s message, built in step 3, already tells the user to pass it, but 1.1 did not list it. It opens the cache with `ignore_version=True`, which provenance records and the terminal footer shows as a warning. (Tasks 5 and 8)
10. **`-v` and `-q`, and a short log format.** 1.1 said nothing about logging. Default level `INFO` so rate-limit `ETA:` lines and the sync summary are seen; `-q` gives `WARNING`, `-v` gives `DEBUG`. Lines read `ERROR: <message>` except at `DEBUG`, which keeps loguru's time and source location. Logs go to stderr so `--format json` can be piped. (Tasks 9 and 10)
11. **The exit status table.** 1.1 listed some errors by name; 1.2 catches the `FetchError` and `StatsError` bases (so `GraphQLError` and `InvalidRequestError`, which 1.1 left out, exit 1 too), maps cappa's own parse failures to 2, and logs any other exception with its traceback and exits 1, rather than letting Python print a second traceback. (Task 10)
12. **`cache info` reads without opening.** `Cache.open` creates the file, checks the identity and raises `CacheVersionError`, so `cache info` could not diagnose the one problem it is most needed for. The fetch spec gains `inspect_cache(path)`, plain SELECTs on its own connection with no schema, identity or pragma writes, returning a `CacheInfo` with the identity differences. A missing cache is reported, not created. (Tasks 3 and 9)
13. **`cache clear` deletes without prompting.** It removes the file and its `-wal` and `-shm` files through the fetch spec's new `clear_cache`, and logs each path. The cache is derived data that the next report refetches, so a confirmation prompt would only get in the way of scripts. (Tasks 3 and 9)
14. **The terminal layout is fixed.** 1.1 said "Rich tables ... and sparklines or bar charts". 1.2 sets the order (title, activity by period, trends, by repository and by author, top contributors, unavailable, provenance), marks partial periods with ` *`, puts a Total row under the period table with contributors taken from the top-contributors table (contributors cannot be summed over periods), shows signed net lines so nothing relies on colour, and shows the first 20 top contributors (the JSON keeps all). (Tasks 5 and 6)
15. **A versioned JSON shape.** 1.1 said "dumps the result". `Bucket` keys and `timedelta` values are not JSON, so 1.2 fixes the shape (`points` as a list of `{label, start, value}`, durations as `"<seconds>s"`, which the settings parser reads back) and adds `format_version: 1`, as the shared versions rule asks for anything a later reader depends on. Step 9's `/api/stats` reuses it. (Task 4)
16. **`wambatic.cli` is the composition root.** The system spec's layering said `reports` imports `stats` only, but something has to build the `Fetcher`. `cli` may import every layer; `wambatic.reports` stays clear of `wambatic.fetch` until step 9's web app. The layering test enforces both. (Task 12)
17. **How the command is installed.** A `[project.scripts]` entry `wambatic = 'wambatic.cli:run'` and `src/wambatic/__main__.py`, rather than a `bin/` wrapper, so `uv sync` puts `wambatic` on the virtualenv's path. (Task 10)
18. **A README user guide.** The repository has no README, and the shared user-guides rule requires one in the commit that adds CLI flags. Task 11 writes `README.md` (install, token, report, cache, config file, exit statuses). `pyproject.toml`'s `readme` stays `AGENTS.md`. (Task 11)
19. **The `Renderer` protocol waits for step 7.** With one renderer it has no caller; step 7 adds it with the second. (coverage table)
